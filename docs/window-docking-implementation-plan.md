# FloatTodo 窗口控制与悬浮贴边实施计划

日期：2026-09-16  
状态：待实施；本文件只定义方案，不表示功能已完成。  
依据：当前 WPF 项目静态审查及文末微软官方文档。

## 1. 目标与架构决策

采用 **自定义标题栏拖动 + WindowChrome 系统边框缩放 + 应用自有吸附/隐藏状态管理**。

FloatTodo 是悬浮工具面板，标题栏拖动需要应用自定义的磁吸和隐藏行为，因此选择自定义平移。普通桌面主窗口仍应优先使用系统移动行为；此方案不是所有 WPF 窗口的通用替代品。

本方案不以未经验证的 QQ 实现为依据，不承诺“零 Snap”“固定帧率”或预定代码缩减比例。对键盘窗口命令、系统缩放及不同 Windows 版本的行为，以明确的产品约束和实际验收为准。

第一版完成：

- 标题栏自由拖动，支持左右吸附和主动拉脱。
- 保留系统边框缩放，宽度范围 260～560 DIP，默认 320 DIP；默认高度 560 DIP、最小高度 360 DIP。
- 仅在具备安全隐藏空间的左右边缘自动隐藏，并保留可交互的唤出条。
- 支持多显示器、负坐标、混合 DPI 和显示器布局变化。
- 保持置顶、自动隐藏、托盘显示三个行为独立。

第一版不实现顶部/底部自动隐藏、桌面工作区预留、任意显示器接缝隐藏、独立唤出条 HWND、全局键盘拦截及新的设置存储系统。

## 2. 用户可见行为

| 场景 | 预期行为 |
|---|---|
| 按住标题栏空白区域移动 | 越过系统拖动阈值后开始平移；标题栏按钮不启动拖动 |
| 接近左右工作区边界 | 磁吸至边界，保留用户选择的尺寸 |
| 从吸附位置拉开 | 超过脱离阈值后恢复自然拖动，不跳到其他位置 |
| 跨显示器移动 | 能穿越左右及上下排列的显示器，不被原显示器边界锁住 |
| 松开鼠标 | 提交吸附或浮动状态，修正最终位置，重新评估隐藏资格 |
| 按 Esc | 取消拖动，恢复开始位置及吸附状态；原显示器消失时恢复到可见位置 |
| 意外丢失捕获/停用窗口 | 安全结束拖动，保留当前有效位置，不残留拖动状态 |
| 拖动系统边框 | 使用系统缩放；吸附时固定贴边侧，另一侧改变尺寸 |
| 悬停隐藏条 | 延迟展开，不激活窗口、不抢键盘焦点 |
| 点击面板或托盘打开 | 允许激活；托盘打开必须得到可见、可操作的展开面板 |
| 关闭自动隐藏 | 停止隐藏计时和收起动画，已隐藏面板立即开始展开 |
| 切换置顶 | 只改变置顶，不隐式切换自动隐藏 |
| 移动到双屏接缝 | 可以吸附；隐藏空间不安全时保持展开 |

尺寸使用 DIP。Win32 几何运算使用物理像素，两者不得以含糊的 `px` 混用。小工作区无法容纳最小高度时，优先保证标题栏与退出/恢复操作可达；必要时降低运行时高度下限至可用高度，并让内容滚动，保留用户偏好尺寸用于恢复。

## 3. 模块职责与文件改动

保持当前项目结构，不建立通用窗口框架。仅抽取需要独立测试的几何和状态规则。

| 文件/模块 | 改动职责 |
|---|---|
| `Controls/TitleBar.xaml(.cs)` | 提供拖动区域；过滤按钮等交互元素；转交输入，不直接设置窗口位置或调用 DragMove |
| 新增 `Services/WindowDragController.cs` | 捕获鼠标，维护拖动阈值、屏幕坐标锚点，发出开始/更新/结束/取消动作，处理输入异常结束 |
| `Services/WindowDockService.cs` | 统一协调位置、吸附、计时器、动画和操作状态；维护宿主显示器及展开矩形 |
| `Interop/MonitorHelper.cs` | 获取显示器列表、工作区、候选目标屏、DPI；处理屏幕拓扑刷新 |
| `Interop/NativeMethods.cs` | 补齐实际使用的矩形、显示器、窗口消息 API；避免堆积未使用声明 |
| 新增 `FloatTodo.Core/Windowing/DockGeometry.cs` | 无 WPF 依赖的候选矩形、吸附/拉脱、可见性和隐藏安全性计算 |
| `Core/Models/AppSettings.cs` | 保留现有公开枚举的兼容性；运行时操作状态不混入持久化视图设置 |
| `MainWindow.xaml(.cs)` | 保留 WindowChrome；将托盘、置顶、自动隐藏和窗口生命周期动作交给服务 |
| `tests/FloatTodo.Core.Tests` | 添加几何及必要的状态转换测试 |

窗口位置只能由协调服务及其内部平台适配方法写入。系统缩放和 WPF DPI 处理造成的位置变化属于外部输入，服务读取结果并更新状态；不得再由多个事件处理器同步抢写 `Left/Top`。

## 4. 坐标、显示器与吸附规则

### 4.1 坐标约定

- 在有效的 Per-Monitor DPI 感知上下文下，使用 `GetCursorPos`、`GetWindowRect` 和显示器物理矩形处理拖动几何；实施前核实进程和 HWND 的实际 DPI awareness，不能仅凭目标框架推断。
- 起始位置读取真实 HWND 矩形，不用 `Window.Left × 当前 DPI` 推算整个虚拟桌面的绝对位置。
- WPF 负责布局尺寸；阈值、把手宽度及最小尺寸在使用处转换为目标显示器对应的物理像素。
- 明确窗口外框与可见边框的差异。必要时读取 DWM 可见边框边界，并将边框偏移转换回 HWND 定位矩形；不得把阴影或不可见缩放边框算成把手。
- 跨 DPI 时先确认 WPF 对 `WM_DPICHANGED` 的既有处理；让框架完成其应有的布局与缩放，再同步服务状态。不得额外应用第二次缩放。
- DPI 或实际窗口尺寸变化后重算鼠标锚点与候选矩形，保持光标相对标题栏的位置连续。

### 4.2 目标屏与工作区

- 自由拖动时按光标所在屏选择候选显示器；光标落入显示器间隙时，按候选窗口矩形与显示器的交叠/最近距离选择。
- 磁吸前先选目标屏，不能根据已被约束的旧窗口位置反推目标屏。
- 拖动期间允许跨越屏幕边界；顶部限制只在不会阻断跨屏的情况下应用。松手后保证标题栏可见，并在可容纳时将面板约束到目标工作区。
- 吸附后保存宿主显示器标识、吸附边和展开矩形。收起动画期间不因窗口滑出而重新选宿主屏。
- 显示器、分辨率、工作区或 DPI 改变时取消过期动画，刷新拓扑，重新计算展开/隐藏位置；原宿主不存在时回到最近有效工作区并展开。

### 4.3 磁吸与拉脱

- 初始调校参数：吸附阈值 16 DIP，脱离阈值 28 DIP；参数集中定义，验收时按手感调整。
- 使用进入阈值小于脱离阈值的滞回规则，避免边缘反复切换。
- 距离基于“光标对应的自然候选矩形”计算，不能基于上一次已经吸附的矩形累积增量。
- 吸附只在有限距离内触发，不能把所有越过屏幕边界的位置都强行拉回。
- 目标屏变化或离开有效边段时解除旧吸附候选；只有状态实际改变才发送通知。

## 5. 拖动与系统缩放生命周期

统一入口：`BeginDrag`、`UpdateDrag`、`EndDrag`、`CancelDrag`；完成与取消操作必须幂等。

拖动开始时停止隐藏/悬停计时器，取消动画并从当前真实窗口位置继续。鼠标捕获失败时不进入拖动状态；只有左键按下且跨过系统拖动阈值后才开始移动。监听 `LostMouseCapture`、Esc、窗口停用、隐藏和真正关闭；释放捕获前先清除内部拖动状态，避免事件重入重复完成。

每次更新按绝对光标位置计算候选矩形，必要时调用：

```text
SetWindowPos(..., SWP_NOSIZE | SWP_NOZORDER | SWP_NOACTIVATE)
```

常规拖动不施加追赶动画；没有位置变化时不重复调用。检查 API 失败并记录诊断信息，不能将未成功的定位当作实际位置。

保留 `WindowChrome.CaptionHeight = 0` 和系统缩放边框。系统 `WM_ENTERSIZEMOVE/WM_EXITSIZEMOVE` 用于协调系统移动/缩放，不再承担自定义鼠标拖动生命周期。通过实际 `WM_SIZING/WM_MOVING` 或相应命令区分操作，不能把二者都标为拖动。

吸附缩放规则：右吸附保持右边不动，左吸附保持左边不动；在系统提供的候选缩放矩形上约束尺寸和贴边位置，避免 `SizeChanged` 中反复纠正造成竞争。缩放期间禁止自动隐藏，结束后更新展开矩形并重新评估隐藏资格。

保留有实际用途的最小/最大尺寸约束。最大化、双击、系统菜单和键盘入口单独验收；需要阻止最大化时采用最小必要的窗口样式/命令策略。不更改全系统 Snap 设置，不使用全局键盘 Hook。

## 6. 状态和自动隐藏

运行时状态分开表达：

- 操作：Idle、Dragging、SystemMoving、Resizing。
- 吸附：None、Left、Right，以及宿主显示器。
- 展示：Visible、Showing、Hiding、Hidden。

对现有 `DockState` 的 UI 通知由这些状态推导，不增加互相矛盾的布尔标记组合。隐藏必须有有效吸附边；操作进行中不得收起。

| 输入 | 状态处理 |
|---|---|
| 开始拖动/系统移动/缩放 | 停止所有自动隐藏计时，取消动画，进入对应操作状态 |
| 结束操作 | 回到 Idle，提交有效位置和吸附状态，再判断是否允许隐藏 |
| 鼠标离开面板及关联交互区域 | 满足资格后启动一次隐藏计时 |
| 指针重新进入/打开关联菜单 | 取消隐藏计时；收起中则从实际位置反向展开 |
| 悬停隐藏条 | 启动一次展开延迟；持续 MouseMove 不反复重置计时 |
| 悬停延迟到期 | 重新检查鼠标是否仍在把手区域，符合才展开 |
| 关闭自动隐藏/托盘打开 | 停止收起，展开到可见位置；托盘打开额外激活 |
| 屏幕拓扑改变 | 取消动画，重新求位置与资格，必要时解除吸附并展开 |

隐藏资格必须同时满足：Idle、自动隐藏开启、有效吸附、鼠标不在面板或相关弹出界面内、没有编辑/菜单/拖放等活动交互、隐藏空间安全。不能只用主窗口 `IsMouseOver` 判断 Popup 或 ContextMenu 的交互状态，也不能简单规定窗口激活就永不隐藏。

初始参数沿用隐藏延迟 500 ms、展开延迟 80 ms、可见条宽度 6 DIP、动画时长 180 ms。所有延迟到期时重新检查条件，而不是直接执行旧请求。

### 隐藏空间的安全判定

计算展开矩形、隐藏目标矩形及滑动过程中覆盖区域。只有被移出的主体不会落入任意其他显示器可见区域，而且把手确实位于可交互的可见区域时，才允许滑出隐藏。必须考虑窗口完整高度和不规则屏幕排列，不能只比较显示器左右坐标。

如果工作区边缘与显示器物理边缘不同，例如侧边任务栏，第一版不在该侧滑出隐藏，避免覆盖任务栏或让把手不可达。系统自动隐藏任务栏的边缘也应检测冲突；无法可靠判定时禁用该侧自动隐藏，托盘仍可恢复。

## 7. 动画、恢复与资源释放

- 保留基于实际经过时间的短动画；`CompositionTarget.Rendering` 只用来调度，不宣称固定帧率。
- 显示器信息在操作开始时确定，拓扑变化时失效；避免每帧重新选择宿主屏。
- 新拖动、反向展开或拓扑变化中断动画时，从真实当前矩形继续；旧完成回调不得提交过期状态，可使用操作版本号。
- 悬停展开保持 `NOACTIVATE`；置顶只能由独立设置改变。
- 尊重系统动画偏好，禁用动画时直接提交最终位置。
- 托盘隐藏/恢复与贴边隐藏保持不同语义；每次恢复先检查位置是否仍可见。
- 为服务实现明确清理入口：停止计时器，解除 Rendering、窗口事件及 HwndSource Hook，释放输入捕获。只在真正退出/销毁时释放，不能在取消关闭并隐藏到托盘时误释放。
- 本次只保证运行时恢复。后续接入设置持久化时存储展开位置及宿主信息，不存储滑出后的隐藏坐标作为下次启动位置。

## 8. 分阶段实施与完成条件

### 阶段 A：建立基线与最小诊断

1. 记录现有拖动、吸附、缩放、隐藏和托盘行为。
2. 核实实际 DPI awareness、WindowChrome 命中区域及当前窗口样式。
3. 添加可关闭的调试日志，仅在状态变化或 API 失败时记录操作、矩形、显示器和 DPI，不逐帧刷日志。

完成条件：能复现现有问题，确认标题栏与系统边框事件入口；不改变用户行为。

### 阶段 B：几何及多屏规则

1. 提取物理坐标几何函数、目标屏选择、吸附滞回和隐藏空间判定。
2. 完成负坐标、跨屏、不同工作区及隐藏安全性的单元测试。
3. 明确 DIP 转换边界和可见外框偏移。

完成条件：几何算法可脱离 WPF 验证，双屏接缝不会被误认为安全隐藏区。

### 阶段 C：替换标题栏拖动

1. 引入拖动控制器及统一生命周期，一次性迁移原来依赖系统移动消息的计时器/动画协调逻辑。
2. 移除标题栏 `DragMove()`，接入捕获、取消和屏幕坐标平移。
3. 接入磁吸与拉脱，支持跨 DPI 重建锚点。

完成条件：拖动过程中没有自动隐藏竞争，丢失捕获后可再次正常拖动，上下排列显示器可跨越。

### 阶段 D：系统缩放与窗口命令

1. 保留并验证原生缩放，区分系统移动、系统缩放和自定义拖动。
2. 在候选缩放矩形中处理吸附锚边，移除竞争性的 SizeChanged 定位逻辑。
3. 按实测结果保留最小必要的窗口样式、最大化限制和尺寸约束。

完成条件：左右吸附后的缩放均无抖动和跳位；最大化/键盘入口行为符合工具窗口要求。

### 阶段 E：隐藏状态及生命周期

1. 接入隐藏安全性、宿主显示器锁定、延迟回查和动画中断处理。
2. 修复关闭自动隐藏后仍隐藏、悬停计时反复重置等行为。
3. 接入屏幕拓扑变化、托盘恢复和资源释放。

完成条件：接缝处不滑入邻屏，动画可打断，屏幕断开后窗口可找回，真正退出后无残留订阅。

### 阶段 F：整体验收与整理

1. 执行以下测试矩阵及构建/单元测试。
2. 删除已无用途的 Hook、旧动画辅助方法及重复状态，仅删除已验证没有调用者的代码。
3. 记录验证系统、屏幕布局、缩放比例和未覆盖环境；将实测参数更新回本文件。

完成条件：全部必测场景通过；无法验证的硬件环境明确列为未验证，不能用模拟外观代替 Windows 10 真机测试。

## 9. 验证矩阵

| 类别 | 必测场景与判断 |
|---|---|
| 几何单测 | 左右吸附临界值、进入/脱离滞回、自然位置拉脱、负坐标、窗口大于工作区、双屏接缝和局部相邻屏幕 |
| 状态测试 | 失去捕获、重复结束、拖动中隐藏计时到期、动画反向、关闭自动隐藏、旧动画完成回调失效 |
| 单屏 | 100%、125%、150%、200%；四边拖动和四角缩放；顶部不意外最大化；面板可恢复 |
| 多屏 | 左右/上下排列、负 X/Y、100%+150% 混合 DPI；双向跨屏无明显位置跳变，能穿越接缝 |
| 隐藏 | 安全外边缘正常隐藏；接缝/侧边任务栏不错误隐藏；持续移动鼠标经过把手也能展开；离开后不误展开 |
| 输入异常 | 按 Esc、Alt+Tab、捕获被其他控件夺取、按住鼠标移出窗口、拖动时隐藏到托盘 |

| 系统入口 | 双击标题栏、Win+方向键、可用的系统菜单命令、边框靠近屏幕边缘缩放；记录实际行为 |
| 生命周期 | 显示器拔出、改分辨率/DPI、任务栏位置变化、休眠恢复、托盘恢复、真正退出 |
| 系统兼容 | 实际支持的 Windows 10/11 环境分别检查；关闭 Mica 或改圆角不代表完成 Windows 10 验证 |

执行 `dotnet build FloatTodo.slnx` 和 `dotnet test FloatTodo.slnx`。本文件为文档变更，编写阶段不以构建通过替代未来功能验证。
